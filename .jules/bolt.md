## 2026-07-24 - [N+1 query with nested relationships in Jinja2 templates]
**Learning:** Fetching full tables (e.g., Customers, Tariffs) into Python dictionaries for lookups in templates is a severe anti-pattern in large baze-danych systems. Replacing this with SQLAlchemy `joinedload` on relationships (like `Subscription.customer` and `Subscription.tariff`) reduces queries from N+M+3 to 1. Additionally, accessing properties like `tariff.monthly_price_gross` can silently trigger a nested N+1 query if `vat_rate` is not eager-loaded via nested joinedload (i.e., `joinedload(models.Subscription.tariff).joinedload(models.Tariff.vat_rate)`).
**Action:** Always identify Jinja template lookups and property accesses on related models, and use nested `joinedload()` in SQLAlchemy queries to prevent secondary query loops on lazy-loaded fields.
