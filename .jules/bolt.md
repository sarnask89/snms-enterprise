## 2026-08-15 - Eager Loading Relationships vs. Full-Table Dictionary Scans in HTML Routers
**Learning:** Legacy HTML routes in FastAPI/Jinja2 often fetched all rows from related tables into in-memory dictionaries (`customers = {c.id: c for c in db.scalars(select(models.Customer)).all()}`) to display related names/codes in views. This created an $O(N)$ data transfer bottleneck on every request. Utilizing SQLAlchemy's `selectinload` (or `joinedload`) eager loading options batches relationship loading into $O(1)$ batched queries and eliminates redundant memory allocations.
**Action:** When auditing or optimizing list views in FastAPI routers, remove full-table dictionary fetches, add relationship eager loading options (`selectinload`/`joinedload`) to the primary SELECT query, and access related attributes directly on the entity in Jinja2 templates (e.g., `t.customer.last_name` instead of `customers[t.customer_id].last_name`).
